HOI4 CRASH GUIDE

HOI4 crashes on the same date every time

A crash that repeats on the same in-game date is valuable evidence. Something deterministic is often being evaluated or completed around that time, so narrow the search to content that can fire then instead of reviewing the whole mod.

Quick answer

Load a save shortly before the crash, reproduce it once, and examine the freshest log. Then check scheduled events, focus completions, decisions, on-actions, scripted effects, AI-triggered content and state changes that can execute around that date.

Why the date matters

  • A national focus may complete on that day.
  • An event or decision timeout may expire.
  • A periodic on-action or scripted check may run.
  • AI-controlled countries can execute the same broken content even if the player never interacts with it.
  • A war, annexation, state transfer or tag-related transition can expose an invalid reference only when the game reaches that state.

Isolation workflow

  1. Keep a save one or two days before the reproducible crash.
  2. Launch, reproduce once, then stop. Do not overwrite the useful fresh log with unrelated later launches.
  3. Look first for messages timestamped or emitted near the end of error.log.
  4. Search your project for event IDs, focus IDs, state IDs or file paths named near those messages.
  5. Temporarily disable one suspected event chain, focus completion or periodic script at a time.
  6. When the crash date moves or disappears, reduce the suspect block further.

Do not assume the last log line caused the crash

The final message can be a symptom, and some fatal failures produce little useful text in error.log. Correlate log evidence with what changed in the project and what the simulation is scheduled to do on that date.

How Paradox Doctor helps

Use the normal diagnosis to group repeated log messages and check project structure. If the crash appeared after recent edits, Project Regression Doctor can compare the last working folder with the broken folder and rank changed files by path risk, structural differences and log mentions.
