HOI4 UPDATE GUIDE

HOI4 mod broke after a game update

When a mod worked on an older Hearts of Iron IV version and fails after an update, do not start by rewriting everything. First separate a simple descriptor warning from an actual compatibility break in scripts, data structures, map files or dependencies.

Quick answer

Update the declared supported version, reproduce the failure on the new game version, then compare a last-known-good project with the current one. Prioritize errors tied to files or systems touched by the game update rather than treating every warning as fatal.

Common failure categories

  • Descriptor mismatch: supported_version is stale. This is easy to fix but may not be the real bug.
  • Script behavior changed: an effect, trigger, scope or object field may no longer behave as before.
  • Vanilla IDs or paths changed: your mod may reference content that moved, changed or was removed.
  • Map/state compatibility: map-related content is sensitive to changes in vanilla state, province or strategic-region data.
  • Dependency lag: a required mod may not yet support the new game version.

Migration workflow

  1. Keep a copy of the last project version that worked.
  2. Test with only your mod and required dependencies enabled.
  3. Reproduce one specific failure and capture a fresh error.log.
  4. Check supported_version, then move on if the symptom persists.
  5. Search the log for your changed file paths and object IDs.
  6. Compare working and broken project folders to see what changed on your side.
  7. For references into vanilla/dependencies, load a local reference folder when possible before declaring an ID missing.

Do not confuse warning cleanup with migration

Older mods can accumulate warnings that were already present when the mod worked. Fix reproducible blockers first. A warning becomes much more useful when it correlates with the subsystem that actually broke after the update.
