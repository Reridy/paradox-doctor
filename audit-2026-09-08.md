# Paradox Doctor product audit — 2026-09-08

## Problems found in v3
- First-visit game modal blocked the entire site and duplicated the header game selector.
- The page read like a landing page before it behaved like a utility; the diagnostic workspace started too far down.
- Marketing/research/roadmap blocks were more prominent than the actual workflow.
- A numerical 0–100 “health score” implied precision the heuristic scanner did not have.
- Workflow-v3.js monkey-patched global functions from script.js, making result rendering and future maintenance fragile.
- Repeated findings could fail v3 card decoration because rendered titles included a frequency suffix while lookup used the raw title.
- Game switching could leave stale findings visible under a different game profile.
- The BOM check used decoded text, which is not a reliable way to detect a UTF-8 BOM.
- Some heuristics were too strong: a state without a buildings block was promoted toward root-cause status even though it can be valid.
- Strategic-region coverage checks could create false positives when only a partial set of region files was selected.
- Baseline comparison required exporting and importing a report instead of offering a one-click local baseline.
- The raw research Markdown link in the public footer looked like an internal artifact rather than a finished product.
- Mobile navigation disappeared entirely below the desktop breakpoint.

## v4 decisions
- One cohesive app script, one primary diagnosis action, no blocking game modal.
- Compact product intro followed immediately by a two-input workspace.
- Remove the fake precision score and use honest states: Needs attention / Review warnings / No supported issues found.
- Distinguish high-confidence checks from heuristics in every finding.
- Detect BOM from raw bytes, not decoded text.
- Demote weak state/building checks to informational heuristics.
- Do not claim strategic-region coverage unless the available context justifies it.
- Save a regression baseline locally in one click; keep JSON import/export for portability.
- Keep ignore fingerprints local and game-specific.
- Make reference comparison explicitly optional and informational unless the collision is deterministic.
- Add scan coverage chips so users know what was and was not checked.
- Add a guides hub, project-level 404 page, accessibility improvements, responsive layout and automated static-site quality checks.
