HOI4 로그 가이드

호이4 error.log에서 실제 오류 찾는 법

큰 error.log는 위에서부터 전부 고쳐야 하는 할 일 목록이 아닙니다. Hearts of Iron IV는 영향이 적은 경고, 의존성 관련 메시지, 그리고 앞쪽의 구조 오류 하나 때문에 연쇄적으로 생긴 오류를 함께 기록할 수 있습니다. 목표는 모든 줄을 무작정 고치는 것이 아니라 가장 먼저 확인할 만한 원인을 찾는 것입니다.

빠른 답

문제를 한 번 재현해 최신 로그를 만들고, 반복 메시지는 묶어서 보세요. 최근 수정한 파일이나 줄을 직접 가리키는 오류를 우선 확인하고, 긴 연쇄 오류가 있다면 뒤쪽의 unknown key나 wrong scope보다 앞쪽의 parser 오류를 먼저 확인하는 편이 좋습니다.

어디부터 확인할까?

  1. 문제가 재현되는 모드 구성으로 게임을 실행합니다.
  2. 문제를 한 번 발생시킨 뒤 게임을 종료합니다.
  3. Documents/Paradox Interactive/Hearts of Iron IV/logs/error.log의 최신 파일을 엽니다.
  4. 내 모드 내부 경로, 최근 수정한 ID, 또는 고장 난 기능과 관련된 단어를 검색합니다.
  5. 같은 오류가 반복된다면 복사본을 전부 보지 말고 가장 먼저 등장한 서로 다른 메시지를 조사합니다.

가치가 높은 신호

  • 파일 + 줄 위치: 최근 수정한 파일을 직접 가리킬수록 유용합니다.
  • Unexpected token / parser 오류: 잘못된 블록 하나가 뒤쪽에 많은 오류를 만들 수 있습니다.
  • 중복 ID 또는 localization key: 모호한 경고보다 재현하고 확인하기 쉽습니다.
  • Map/state 참조: province나 state를 수정한 뒤 문제가 시작됐다면 특히 중요합니다.
  • 동일한 반복 메시지: 여러 번 고치려 하지 말고 공통 원인 하나를 찾습니다.

자주 빠지는 함정

  • 로그의 마지막 줄이 자동으로 크래시 원인인 것은 아닙니다.
  • 실제 경고라고 해도 지금 조사 중인 증상의 원인이라는 뜻은 아닙니다.
  • 내 모드 폴더만 보면 바닐라나 의존 모드의 참조가 없는 것처럼 보일 수 있습니다.
  • 같은 문제를 깨끗하게 다시 재현하지 않고 여러 번 실행하면 오래된 로그 내용이 판단을 흐릴 수 있습니다.

프로젝트와 로그를 같이 사용하기

로그는 실제 프로젝트 파일과 함께 볼 때 더 강력합니다. Paradox Doctor는 반복되는 엔진 메시지를 묶고, 소스 위치를 추출하고, 선택한 프로젝트 파일과 비교해 비교적 확정적인 구조 문제를 신뢰도가 낮은 추정보다 먼저 보여줍니다.
