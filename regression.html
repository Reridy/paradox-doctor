    HOW RANKING WORKS

    A suspect list, not a verdict.

    The tool does not claim the top file caused the bug. It prioritizes files using reproducible signals and shows the reasons for each ranking.

    01

    Find actual changes

    Added, removed, and text-modified files are compared by relative project path.

    02

    Look for risky changes

    Structural imbalance, removed IDs, and game-sensitive folders increase suspicion.

    03

    Correlate error.log

    If the fresh log mentions the changed path or its subsystem, that change moves higher.
